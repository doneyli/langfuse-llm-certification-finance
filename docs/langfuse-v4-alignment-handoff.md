Writes are safe: `POST /api/public/scores` (`cert_common.py:230`, `monitor_production.py:223`), `/score-configs`, `/annotation-queues*`, `/v2/datasets` all remain. Note the OpenAPI spec now documents `POST /scores` as a **list** body returning 202/207; prefer the SDK's `create_score` / `Evaluation` over raw single-object POSTs.

**2. SDK 3.x is deprecated on Cloud v4.** The compatibility matrix lists Python v3 as *Deprecated* against Cloud v4. `run_experiment` in 3.x/4.x still calls the legacy `POST /dataset-run-items` internally (v4 keeps it only as a stale compat shim); Python v5 records experiments via OTel attributes. v5 needs Python ≥ 3.11 (repo: 3.11 ✓) and Cloud or self-hosted ≥ 4.59.0.

**3. Run metadata gap (verified live).** The portal's whole threshold display (`cert_common.recorded_gate`) reads `gate_thresholds` / `threshold` / `model` from run metadata. The deprecated runs endpoint returns it; **`GET /experiments?fields=metadata` returns `{}` for every existing run** (they were produced by SDK 3.x, which only stored run metadata on the legacy dataset-run row). SDK v5 emits experiment metadata as the `langfuse.experiment.metadata` span attribute, so *new* runs will carry it — this must be verified with a spike after the upgrade, and the portal must tolerate `{}` for historical runs (status still comes from the `certification_result` experiment score; bar shows `—`).

**4. Trace-level LLM-as-a-judge guidance is dead.** README (`:732`) and `docs/ai-engineering-loop.md:124` tell readers to configure a judge "on Live Observations" the old way; trace-level evaluators stop producing results at the cutover. Current model: an **evaluator** (how to score) + a **rule** (which observations; `isRootObservation = true` filter) at observation level, created in UI or via `POST /api/public/v2/evaluators` + `/v2/evaluation-rules`.

### A2. P1 — wrong or obsolete today

1. **`cert_common.persist_run_evaluations` is a duplicate write.** The installed SDK (3.14.6) already persists `run_evaluators` results to the dataset run (`create_score(dataset_run_id=…)` in `_client/client.py:2876-2886`), and the live project shows `certification_result` with `subject.kind = "experiment"`. The workaround then writes a *second* copy onto the first item's trace, and `portal/langfuse_client.py:_build_cert_index` (anchor scores → trace fetch → `metadata.experiment_run_name`) plus README `:447-448` and `docs/usecase-runbook.md:104` teach that location. Remove it; read run-level scores from `GET /experiments?fields=scores`. Affected: `cert_common.py:196`, `run_certification.py:445`, `run_usecase_certification.py:239`, `tests/test_certification.py:81`, `tests/test_usecase_foundation.py:224` (asserts the attribute), `docs/usecase-architecture.md:56,113`, `docs/usecase-certification.md:266,269`.
2. **Binary scores are NUMERIC; Langfuse has BOOLEAN pass/fail scores.** `certification_result`, `regulatory_compliance`, `tool_use_correctness`, `numerical_accuracy`, `exact_match`, `sentiment_accuracy` are all 0/1 but registered `NUMERIC` (`setup_score_configs.py:33-140`). BOOLEAN scores (value 0/1 on write, `true/false` on v3 reads) unlock: boolean dashboard widgets and **alerts on the true-rate** (2026-07-21), the Score Analytics 2×2 confusion matrix vs human labels, and the Experiments view's pass/fail rendering. The SDK `Evaluation` already accepts `data_type="BOOLEAN"` (even in 3.14.6). Keep `groundedness`, `completeness` and all `avg_*` NUMERIC.
3. **Prompts are fetched but never linked to generations.** `agents/base.py:traced_generation` opens the generation span without `prompt=`, so Langfuse's Prompts → *Metrics* tab (per-version scores, latency, cost) is empty — the Edge B story ("promote a prompt, re-run the gate, compare versions") has no per-version evidence in Langfuse. `start_as_current_observation(..., prompt=<PromptClient>)` and `propagate_attributes(prompt=…)` (SDK ≥ 4.14) exist. Also: the **model gate's Claude path is untraced** — `run_certification.call_anthropic_native` is a raw `anthropic.Anthropic().messages.create` with no generation observation (no model/usage/cost on model-gate traces); only the OpenAI-compatible path is auto-traced.
4. **Observation types / agent graphs.** Agents emit `generation`/`span`/`tool` only. Langfuse renders an **agent graph** for any trace containing an observation type other than span/event/generation, and the SDK supports `agent`, `tool`, `chain`, `retriever`, `evaluator`, `guardrail`. `retrieve-evidence` is a retriever, `compliance-self-check` is a guardrail, each per-item run is an `agent`. In v4 trace input/output come from the **root observation**, which observation-level judges and the `isRootObservation` rule filter rely on.
5. **Self-host stack is v3.** `selfhost/docker-compose.yml` pins `docker.io/langfuse/langfuse:3` / `langfuse-worker:3` and unpinned ClickHouse; upstream `main` is `docker.langfuse.com/langfuse/langfuse:4`, `langfuse-worker:4`, `clickhouse-server:25.12`. v4 minimums: ClickHouse 25.12 (26.4 recommended), Postgres 15, Redis 7. Fresh installs need no migration. Code evaluators on self-host need `LANGFUSE_CODE_EVAL_DISPATCHER` (`insecure-local` = TS/JS only; Python needs `aws-lambda`).
6. **CLI and agent-tooling guidance is stale.** `AGENTS.md:92-115`, `README.md:625-630` use `npx langfuse-cli` and `api traces list` (deprecated resource). Current: `npx @langfuse/cli --env .env api <resource> <action>`; resources now include `experiments`, `experiment-items`, `evaluators`, `evaluation-rules`, `score-configs`, `observations`, `unstable-dashboards`; `--env <path>` still exists; `langfuse get-skill` still exists. The authenticated **Langfuse MCP server** (`https://<host>/api/public/mcp`, Basic auth) is not mentioned anywhere.
7. **README claims that are now false.** `README.md:598` "no API for dashboard creation" (dashboards/widgets/placements API, CLI and MCP since 2026-07-17); the Portal-vs-Langfuse table (`:605-608`) predates Experiments as a first-class concept (2026-04-13), baseline compare, per-item comparison with threshold filters, cross-run charts and annotate/correct-in-context (2026-10-19). "Datasets → Runs" navigation (`AGENTS.md:58,159`, `README.md:318,447`, `docs/usecase-runbook.md:102`) is now **Experiments**. `docs/loop-activation-checklist.md` / `ai-engineering-loop.md` say "one-click UI promotion is open" — Langfuse now has **"+ Add to dataset"**, batch add from the Observations table, and **Corrections** (`dataType: CORRECTION`, `name: output`).
8. **GitHub integration payload** read by `.github/workflows/prompt-recert.yml` (`client_payload.prompt.name/labels`) still matches the current docs. No change needed.

### A3. P2 — enhancements to capabilities the demo already has

1. **Production monitoring as Langfuse-managed evaluators + alert.** `monitor_production.py` polls on cron, scores, and exits 1 "for alerting". Today the same deterministic checks can run inside Langfuse as **code evaluators** (Python stdlib, 2 s, BOOLEAN output, `ctx.observation.output`) attached to a **rule** on live root observations, and `groundedness` can run as an observation-level **LLM-as-a-judge evaluator**; a Langfuse **Alert** on the `regulatory_compliance` boolean true-rate notifies Slack / webhook / GitHub Actions. Keep the script as the air-gapped fallback; add the managed path as the primary story. Human step: an LLM connection in the Langfuse project for the judge.
2. **Corrections close Edge A without the CLI flag.** A reviewer writes the corrected output in the trace/queue UI; `promote_trace_to_dataset.py` can read it (`GET /v3/scores?traceId=…&dataType=CORRECTION`) and use it as `expected_output` instead of requiring `--expected`, keeping the human gate.
3. **Dataset hygiene now has first-class support.** Items upsert by `id` → give golden items deterministic ids (`fb-<financebench_id>`, `fpb-<sha>`, `adv-<n>`) and the "re-running `setup_datasets.py` duplicates items" gotcha (README, `make seed` count guard, `demo_usecase.sh`) disappears. Every item change creates a **dataset version**; SDK v5 records `langfuse.experiment.item.version` and experiments can be pinned to a version — record the version in run metadata and the evidence pack.
4. **Dashboards as code.** The four widgets the README recommends can be created via `POST /api/public/unstable/dashboard-widgets` (`view ∈ observations|scores-numeric|scores-boolean|scores-categorical`, `metrics[{measure, agg}]`, `chartType`) + a dashboard with placements — optional `setup_dashboards.py`, or at least correct the README.
5. **CI shape.** Langfuse now ships `langfuse/experiment-action` + `RegressionError` / `RunnerContext` (SDK ≥ 4.6) and documents an **approved-baseline per-case** regression check (an average can hide a newly failing item — exactly the gap `cicd/README.md` acknowledges). This repo's CI is deliberately credential-free (client-shared) — do **not** enable it; document the shape and optionally add an opt-in `--baseline` check that compares per-item scores against a reviewed experiment via `GET /experiment-items`.
6. **Judge calibration surface.** README promises "compare human scores against automated scores". Langfuse **Score Analytics** does this (confusion matrix, Cohen's κ) but needs both scores to share a data type; `human_groundedness` is 3-category CATEGORICAL while `groundedness` is NUMERIC. Smallest fix: have the judge also emit a CATEGORICAL `groundedness_label` with the same three categories (evaluators may return a list of `Evaluation`s).
